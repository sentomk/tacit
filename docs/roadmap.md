# C++ zk-SNARK 库 · 项目 Roadmap

> 一个用现代 C++ 从零实现的 zk-SNARK 库，底层追求极致性能（编译期参数化、汇编快路径、CUDA 加速），上层落地一个金融场景应用：交易所储备金证明（Proof of Reserves）。

---

## 1. 项目定位

- **技术目标**：现代 C++ 实现有限域、椭圆曲线、配对、NTT/MSM 与 Groth16，性能对标 arkworks、gnark、ICICLE。
- **生态位**：C++ 领域的 libff/libsnark 已长期不维护，现代 C++ 的 zk 库基本是空白。
- **应用目标**：基于本库实现一个端到端的储备金证明系统，作为项目的金融叙事和对外展示。

## 2. 分工

| 方向 | 负责人 | 内容 |
| --- | --- | --- |
| 核心算术与证明系统 | 我 | 域运算、曲线与配对、NTT/MSM、CUDA、Groth16、门面 API |
| 正确性与验证 | 她 | Sage/Python 参考实现、测试向量、arkworks 对拍、性质测试 |
| 兼容性 | 她 | 以太坊格式（EIP-196/197）、Zcash 序列化规范、Solidity 验证合约 |
| 性能报告与对外发布 | 她主导 | benchmark 套件、对比图表、发布文章 |
| 储备金证明应用 | 她（模块 maintainer） | 规格文档、Merkle Sum Tree、电路、端到端 demo |
| 讲解文档 | 她 | 每个阶段一篇原理讲解，兼作博客素材 |

**分工原则**：核心算术可以尽情硬核；她的工作集中在“正确性 + 兼容性 + 应用 + 对外输出”，基本不碰模板元编程和汇编，同时从 Phase 1 起就深度参与。

## 3. 设计原则

- **门面 API 提前设计**：Phase 1 结束时就提供一层非模板接口（具体类型如 `bn254::Fr`、普通函数调用），让不熟悉 C++ 模板的贡献者也能直接写代码。
- **Python 绑定**：通过 nanobind 或 pybind11 暴露核心功能，应用层和测试可以用 Python 完成。
- **可执行规格**：任何需要建模的部分，先有规格文档和 Python 参考实现，再写 C++ 或电路，用测试向量保证一致。
- **开箱即用的开发环境**：提供 devcontainer，新人无需折腾 C++ 工具链即可编译和运行测试。
- **正确性优先**：每个 PR 合并前必须通过参考实现对拍和性质测试。

## 4. Roadmap

### Phase 0 · 基建

**我**
- CMake 工程、GitHub Actions CI
- 单元测试框架（Catch2 或 GoogleTest）、Google Benchmark
- devcontainer
- SageMath 脚本：生成曲线常数（Montgomery 参数、单位根等）

**她**
- 熟悉项目结构和开发流程，跑通 devcontainer 内的编译与测试
- 搭建 Python 测试环境，学习 Sage 基础

### Phase 1 · 有限域

**我**
- 编译期参数化的素域
- Montgomery 乘法
- 扩域 Fp2 / Fp6 / Fp12
- x86-64 `mulx` / `adx` 汇编快路径（ARM64 可后续补充）
- 门面 API 第一版

**她**
- Sage/Python 参考实现 + 测试向量生成，与 arkworks 结果对拍
- 性质测试：交换律、结合律、分配律、`a * a⁻¹ = 1` 等
- C++：基于已有 API 实现求逆（费马小定理）、开平方（Tonelli-Shanks）
- C++：域元素序列化与反序列化
- 讲解文档：《Montgomery 乘法为什么快》

### Phase 2 · 曲线与配对

**我**
- BN254（以太坊预编译合约支持，便于链上验证）
- BLS12-381
- G1 / G2 群运算
- Optimal ate pairing

**她**
- 性质测试：双线性 `e(aP, bQ) = e(P, Q)^(ab)`、非退化性等
- C++：点的压缩与解压、子群检查
- 以太坊兼容：BN254 对齐 EIP-196/197 预编译合约的输入输出格式
- Zcash 兼容：BLS12-381 对齐 Zcash 序列化规范
- 讲解文档：《配对在零知识证明中起什么作用》

### Phase 3 · 多项式与 MSM

**我**
- NTT
- Pippenger MSM
- CUDA 后端

**她**
- Python NTT 参考实现，性质测试：NTT 后再逆 NTT 等于原多项式
- benchmark 套件设计，与 arkworks、gnark、ICICLE 做对比测试
- 结果图表与发布文章

> 🚩 **第一次公开宣传节点**：发布 benchmark 对比报告，由她主导对外发布。

### Phase 4 · Groth16 与接口层

**我**
- R1CS 构建 API
- 兼容 Circom 编译产出的 R1CS 文件
- Trusted setup
- 证明生成与验证，证明格式兼容 snarkjs
- 完善门面 API 与 Python 绑定

**她**
- 证明 / 验证密钥的 JSON 导入导出
- Solidity 验证合约生成模板，在测试网部署验证
- 示例电路（如哈希原像证明）与入门教程

### Phase 5 · 储备金证明应用（她主导）

1. **规格文档**：储备金证明的金融背景、现有方案（Merkle Sum Tree、主流交易所的做法）、安全假设、公开与保密数据的划分。
2. **约束建模**：总负债 ≤ 总资产、每个余额非负（范围证明）、数值上界（防止有限域溢出绕过检查）。
3. **Python 参考实现**：不涉及密码学，只计算正确结果并生成测试向量。
4. **Merkle Sum Tree**：基于门面 API 用 C++ 实现。
5. **电路实现**：使用 Circom 编写，或与我结对用 C++ R1CS API 完成。
6. **端到端 demo**：Python 模拟交易所数据并生成证明；用户可单独验证自身余额被包含；链上合约完成最终验证。
7. **对外输出**：技术博客或 demo 视频。

> 🚩 **第二次公开宣传节点**：发布储备金证明 demo。

### Phase 6 · 可选扩展

- PLONK（通用 setup，无需每个电路单独 trusted setup）
- 更深入的 GPU 优化
- 更多金融场景：合规证明（如证明交易对手不在制裁名单）、隐私信用评估（如证明收入高于门槛）

## 5. Good First Issues 候选

- 为示例电路补充 Python 测试用例与测试向量
- 证明 / 验证密钥的 JSON 导入导出
- 用 Python 将 benchmark 结果绘制成对比图表并放入 README
- Solidity 验证合约生成模板
- 入门教程：从哈希原像证明的例子讲起
- 补充某个运算的性质测试
- 修订或翻译讲解文档

## 6. 协作流程（规格 → 代码）

1. 她编写规格文档：变量、约束公式、边界情况。
2. 她编写 Python 参考实现并生成测试向量。
3. 我或她将规格实现为 C++ 或电路。
4. 用测试向量验证实现与规格一致，通过后合并。

## 7. 对她求职的建议

- 由她独立负责相关 issue 和 PR review。
- 两次公开宣传节点由她对外发布，积累可展示的文章与 demo。
